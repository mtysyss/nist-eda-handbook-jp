# 8.3.1.1. 指数寿命分布（もしくはHPPモデル）試験

#### システムがMTBF要件を満たしているかを指数（もしくはHPP）モデルを検証に用いることは、産業界では一般的である 

指数検定は、ツール、システム、あるいは機器が[平均故障間隔（MTBF）](../section1/apr171.md)に関する信頼性要件を満たしているかを検証するために、産業界で広く用いられている。
システムが定故障（または修理）率であり、それがMTBFの逆数であるという仮定が置かれる。
故障間の待ち時間は、指数分布モデルに従う。

典型的な検定状況は、工場に新しく導入された複雑な装置や工具を、数週間から数ヶ月にわたり綿密に監視することが挙げられる。
その期間中に、あらかじめ定められた故障回数を超えなければ、その装置は**信頼性受入試験に**「合格」となる。

この種の信頼性試験は、しばしば**認定試験**または**製品信頼性受入試験（PRAT）**と呼ばれる。
機器が試験に不合格となった場合、契約上の違約金が科されることがある。
すべては、所定の信頼水準において顧客のMTBF要件を満たすことに掛かっている。

**所定の信頼水準で指定されたMTBFを保証するために、機器やシステムの試験をどの程度の期間実施しなければならないか** 

まず、所定のMTBF目標値（例えば*M*）と信頼水準（例えば $`100(1-\alpha)`$）を設定する。
試験期間を決定するには、もう1つ情報が必要であり、何件までの故障を許容しても、その機器を「合格」とみなすかということである。
許容される故障回数が多いほど、必要な試験期間は長くなる。
しかし、より多くの故障を許容する長い試験には、試験期間中の無作為な「不運」によって正常な機器が不合格となる可能性を低減するという、望ましい特徴がある。

推奨される手順は、$` r = \text{ 許容される不良の数} `$ について反復計算を行い、より大きな *r* を選択すると許容できないほどの試験期間が必要になるまで続ける。
任意の *r* について、対応する試験時間は、*M*（目標値）に、下表の *r* 番目の行と所望の信頼水準の列に対応する係数を乗じることで、簡単に計算できる。

例えば、90％の信頼度で200時間のMTBF目標を確認し、試験中に最大4回の故障を許容する場合、試験期間は 200 × 7.99 = 1598時間となる。
これが許容できないほど長い場合は、許容故障数を 3件に制限し、試験時間を 200 ÷ 6.68 = 1336時間に設定してみる。
最短の試験では故障を一切許さず、所要時間は 200 ÷ 2.3 = 460時間となる。
これらの試験はすべて、機器が合格したときに、90％の信頼度で 200時間のMTBFを保証する。
しかし、試験期間が短いほど、かろうじて許容範囲内の機器であっても不合格となる可能性が高くなるため、供給業者にとっては「不公平」になりがちである。

表中の係数を計算する式は以下の通り。

$$ \text{FAC } = 0.5 \chi_{\alpha; 2(r+1)}^2 $$

ここで、$`\chi_{\alpha; \, 2(r+1)}^2`$ は、自由度 $`2(r+1)`$ を持つカイ二乗分布の $`100(1-\alpha)`$ 百分位数を表す。

**例：** 新しい工場用工具は、80％の信頼度で 400時間のMTBF要件を満たさなければならない。
その工具が許容基準を満たしているかを判断するために、最大2か月間の3交代制運転の時間が与えられている。
適切な試験計画はどのようなものか？。

2ヶ月間の24時間稼働（保守や修理のための休止時間を除いた場合）は、最大で約1300時間に相当する。
$`r = 1`$ に対する 80%信頼度係数は 2.99であるため、400 × 2.99 ≈ 1200 時間（最大 1回の故障を許容）の試験が、実行できる最適である。

#### 複数のシステムを試験することで、必要な試験時間を短縮する

**注：** 類似したツールやシステムを複数、同時に試験対象とすることができれば、指数関数的な試験時間を大幅に短縮できる。
試験時間は「ツール時間」と同じ意味であり、1つのツールが1000時間稼働することは（指数関数モデルにおいて）2つのツールがそれぞれ 500時間稼働すること、あるいは 10個のツールがそれぞれ 100時間稼働することに相当する。
すべてのツールからの故障件数と、すべてのツールの試験時間の合計を単に集計すればよい。
