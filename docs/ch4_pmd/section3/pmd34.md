# 4.3.4. 言及される「最適な」計画の活用の可否

#### 産業界で広く活用される古典的計画
産業界で最も頻繁に用いられている計画法は、「古典的計画法」（完全実施要因計画、一部実施要因計画、ラテン方格計画、Box-Behnken 計画など）である。
これらが広く用いられているのは、それ自体が最適であり、産業工程の基礎にある構造を効率的に解明する上で、極めて優れた役割を果たしてきたからである。

#### 古典的計画が機能しない理由
しかし、表にまとめられた古典的計画では特定の実用的な状況を網羅できない事例も確かに存在する。
つまり、そうした古典的計画は利用者の制約条件に対応していないため、利用者の制約条件により、表にまとめられた古典的計画を使用できない場合がある。
こうした制約条件には、次のようなものがある。

1. 最大実行数の制限：  
<br>
予算や時間に関する利用者の制約により、許容される最大実行回数が少な過ぎたり、あるいは「不規則」過ぎたり（例：「13」）し、古典的計画法――一部実施要因計画法でさえも――では対応できない場合がある。
<br><br>

2. 不可能な要因組合せ：  
<br>
利用者にとって、実行が不可能な要因組合せが存在する場合がある。
こうした組合せは、（均衡と直交性を維持するために）推奨される古典的計画法の一部として指定されることがある。
もし利用者がこの不可能な実行を計画から単に省略してしまうと、結果として、古典的計画の品質や最適性が低下する恐れがある。
<br><br>

3. 多過ぎる水準数：  
<br>
利用を想定している要因数や、一部の要因の水準数が、古典的計画の表には含まれていない場合がある。
<br><br>
4. 複雑すぎる基礎となるモデル：  
<br>
利用者が想定している基礎モデルが過度に複雑（あるいは非線形）であるため、古典的計画法が不適切となることがある。

#### 古典的計画ががない場合
もし利用者の制約条件が、その制約に対応できる古典的計画が存在しないほど厳しいものである場合、利用者はどのように対処すべきか。 

前節で挙げた設計原則（主モデルの性能、代替モデルの性能、推定係数の最小変動など）は、望ましい設計特性という観点からは目指すべき優れた受動的な目標ではあるが、計画を策定するための能動的な形式的な構築方法論という観点からは、ほとんど助けにはならない。 

#### 一般的な最適性基準
この要求に応えるため、表の古典的計画が使用できない利用者の制約条件のときに、計画を策定するための「最適計画」方法論が開発された。
最適計画はさまざまな観点から最適となり得るものであり、ある基準では最適である設計が、他の基準では次善の設計となる場合もある。
相反する基準により、文字通り「アルファベット・スープ」のような多種多様な最適計画方法論が生み出されてきた。
その「スープ」の中で最も一般的な4つの要素は、以下の通りである。 

D-最適計画：母数推定量の一般化分散を最小化する。  
A-最適計画：母数推定量の平均分散を最小化する。  
G-最適計画：予測値の最大分散を最小化する。  
V-最適計画：予測値の平均分散を最小化する。   

#### 要求 1：モデル
最適計画の動機となるのは、利用者が抱える実用上の制約である。
最適計画の利点は、他に適切な仕組みがない場合に、妥当な計画策定方法論を提供できる点にある。
最適計画の欠点は、利用者にはモデルが必要となる点である。
利用者には、このモデルがない場合もある。

すべての最適計画はモデルに依存するため、結果として得られる計画、データ、および解析から導き出される最終的な工学的結論の質は、解析者が仮定したモデルの正しさに依存する。
例えば、特定工程からの応答が実際には3次モデルに基づいているにもかかわらず、解析者が線形モデルを仮定し、それに対応する最適計画を用いてデータを取得し、データ解析を行った場合、最終的な工学的な結論は誤りであり、無効なものとなる。
したがって、手元で策定された計画を得るための代償の一つは、モデルの指定である。
すべての最適計画にはモデルが必要であり、モデルがなければ最適計画生成方法論は使用できず、一般的な設計原則に立ち返らなければならない。 

#### 要求 2：点の候補集合
最適計画方法論を採用する際のもう一つの代償は、利用者が指定する候補点の集合である。
最適計画は、ある連続領域から最良の設計点を設定するものではない――それは数学に求め過ぎである。
最適計画は、候補点のより大きな超集合から *n* 点の最良の部分集合を計算する。
利用者はこの候補点の集合を指定する必要がある。
最も一般的な場合、候補点の超集合とは、分析者が扱いやすいと考える、要因空間の十分に細かい格子上の完全要因計画法である。
格子が細か過ぎ、結果として得られる超集合が過度に大きくなると、最適計画方法論の適用は計算上困難になる可能性がある。

#### 多大な計算資源を要する最適計画
最適計画生成方法論は、計算負荷が高い。
一部の設計（例えば、D-最適）は、基礎となる探索アルゴリズムの効率という点で、他の設計（A-最適やG-最適など）よりも優れている。
ほとんどの数学的最適化技法と同様に、最適計画方法論による結果が実際に真の最適解であることを絶対的に保証するものではない。
しかし、その結果は実用的な観点からは通常満足のいくものであり、いかなるその場しのぎの設計よりもはるかに優れている。

最適計画に関する詳細については、[Montgomery (2001)](../section7/pmd7.md#Montgomery,%20D.C.%20%282001%29) を参照のこと。
